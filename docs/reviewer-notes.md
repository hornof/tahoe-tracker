# Reviewer notes

The human's rulings on past reviews. The reviewer reads this file before every review and follows it. When the human overrides a review item or sets a new rule, the orchestrator adds one line here, with the PR it came from. Newest at the bottom of each section.

## How to write a review
Rules that add to or override `agents/reviewer.md` in the apb plugin.

- An approved mockup is the spec. If a build would differ from it, even to keep an older rule, that's a Decision for Luke before building, never a judgment call (PR #23).
- Write each Decision as one plain question, one sentence of why, and short lettered options. No recaps, no pixel math, no undefined terms, and name things by what Luke sees ("a laptop window narrower than…", not "the phone layout") (PR #23, Decision 6).
